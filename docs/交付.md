## 1. 插件本体

### 1.1 它是什么

`taskboard3` = 一个 **Cordis 插件 bundle**。装进 DSH profile 后提供：

1. **任务板**：科技树视图 / 列表视图 / 详情 / 抽屉 / 工作区；
2. **工具权限**：组图 / 工具清单 / 模板授权三个页签，以及 composer 里的权限浮层入口；
3. **侧栏入口**：任务板、工具权限；
4. **AI 工具面**：`taskboard_*` 工具（DSH 侧注册；`@taskboard/tools` 的同一份定义也可给 MCP）。

### 1.2 包清单：12 个构建包 + 1 个 bundle 壳

`packages/` 下共 **13 个目录**；`AGENTS.md` §四的构建命令列 **12 个包**（bundle 不进 `tsc -b`，
它是 patch 壳）。bundle patch 里实际有 **8 个插件行**（①–⑧）。

| 包 | 一句话 | patch 行 | 关掉 / 缺失的后果 | 可替换 |
|---|---|---|---|---|
| `protocol` | 词汇与判决：9 状态 / 4 组 / 6 关系 / 错误码 / 转移表 | — | 纯库，无运行时行；core / tools / client 构建期依赖它 | 包级 |
| `core` | 领域逻辑 + `CardStore` 端口 + `ToolPolicyStore`（工具档位） | — | 纯库，无运行时行；上层全部建立在它之上 | ❌ |
| `tools` | AI 工具定义层（v2：9 条用户定义 + 原始卡；纯 JSON Schema，MCP / DSH 通用） | — | 纯库；`dsh-tools` 无定义可注册 | ❌ |
| `io` | SQLite 封装（卡 + kv） | — | 纯库；`store` 无默认实现 | ✅ 可换 |
| `store` | 默认存储：`provide('taskboard3Store', …)` 的薄插件 | ① | **任务板整个不激活**（上层 inject 失败） | ✅ 插件行 |
| `dsh-core` | Host 公共设施：唯一 `createTaskboard()`；provide `taskboard3Core` / 默认空间 / `taskboard3Bus` | ② | 其余行全不激活（它们 inject `taskboard3Core`） | ❌ |
| `dsh` | Host 半边：HTTP 路由 + 斜杠命令 + SSE（临时脚手架） | ③ | 界面拉不到数据、命令没了；**AI 工具还在** | ❌ |
| `dsh-tools` | `@taskboard/tools` 的 DSH 适配（`ctx.tools.register`） | ④ | 数据和界面都在，**agent 用不了任务板** | ❌ |
| `dsh-client` | 客户端 UI·通用链（任务板本体视图；2026-11-27 拆出权限链） | ⑤ | 任务板界面消失；**权限 UI 不受影响** | ✅ 插件行 |
| `dsh-agent-guard` | DSH 专属：agent 工具档位守卫 + `GET /api/tools` | ⑥ | 三档位消失、guard 不挂、`/api/tools` 404；**⑦ 权限 UI 跟着整行不激活** | ❌ |
| `dsh-permissions` | 客户端 UI·权限链（工具权限页 / 模板授权 / 组图 / composer 权限框） | ⑦ | 权限入口消失；任务板其它功能不受影响 | ✅ 插件行 |
| `dsh-agent-loop` | DSH 专属：未读上下文注入（不唤醒）+ 无人值守工作泵（followup） | ⑧ | 未读不再注入、无人值守停止推进；其它不受影响 | ✅ 插件行 |
| `bundle` | bundle 壳：`cordis.patch.yml` 里 insert 8 行 | 承载 ①–⑧ | 不装它 = 整个任务板没有入口 | ✅ 插件行 |

### 1.3 bundle 装配：一个 bundle，8 个可独立开关的行

- **装配文件**：`packages/bundle/cordis.patch.yml`，**106 行、8 个 `- id:` insert 行**
  （2026-11-28 实核；行数以文件为准，不要在别处抄死）。
  `packages/bundle/package.json` 用 `dsh.bundle.patch: ./cordis.patch.yml` 指向它。
- **行序**：① store → ② dsh-core → ③ dsh → ④ dsh-tools → ⑤ dsh-client →
  ⑥ dsh-agent-guard → ⑦ dsh-permissions → ⑧ dsh-agent-loop。
- **⑦ 的激活闸门**：Host 半 `inject: ['taskboard3AgentGuard']`
  （`packages/dsh-permissions/src/index.ts:37`）。⑥ 不在 ⇒ ⑦ **整行不激活**
  （不是降级、不是报错；用户会看到权限入口无声消失，这是设计意图）。
- **为什么 ② 与 ③④ 要分行**：`Taskboard` 是内存状态（卡缓存 / 权限档位 / 模板注册表）。
  HTTP 与工具各自 `createTaskboard()` 会产生两份互不可见的状态。⇒ ② 唯一建实例并
  `provide('taskboard3Core')`，③④ inject 它。
- **子包 patch 仍在，但不被装配**：`store` / `dsh` / `dsh-client` / `dsh-permissions` /
  `dsh-agent-loop` 各自保留 `cordis.patch.yml`（单测 / 预览 / 将来拆回独立 bundle 用），
  profile 装配统一由 bundle 文件承载（bundle 文件头注释）。
- ⚠ `packages/bundle/package.json` 的 `description` 还写「一个 bundle，三个插件条目」；
  实际 8 行 ⇒ 描述已漂，以 patch 为准。
- ⚠ bundle patch 的 ① store 行**没有** `config.dataDir`；真实运行靠 profile 补丁层补，
  见 1.5。

### 1.5 数据位置：`dataDir` 契约与 SQLite 单库

**契约**

- `@taskboard/store` 的 `Config.dataDir` 是**必填非空字符串**，本身**没有默认值**；
  `apply` 第一行校验，缺失 / 空串直接 `TypeError`
  （`packages/store/src/index.ts:90-127`）。相对路径按进程 cwd `resolve`（同文件 `:127`）。
- 库文件名固定为 `taskboard3.db`（`packages/io/src/sqlite.ts:76`），建在 `dataDir` 下；
  开启 WAL，所以同目录还会有 `taskboard3.db-wal` / `-shm`（`:134`、`:193`）。
- 一张 `cards` 表 + `workspace_id` 分区，**不是一空间一库**（`packages/core/src/workspace.ts:17`）。

**默认 patch 指向哪里（两处，别混）**

- `packages/store/cordis.patch.yml` 写的是 `dataDir: !!js dshHomePath('taskboard3')`；
  该文件自己注明**未在真实 profile 实测**。⚠ 这份 patch **不在装配链里**（见 1.3）。
- `packages/bundle/cordis.patch.yml` 的 store 行**没有** `config.dataDir`。
- 真实运行由 profile 补丁层补：`tb3-isolated/cordis.patch.yml` 里
  `- id: taskboard3-store` + `config.dataDir: !!js dshHomePath('taskboard')`。
  实际库文件落在 `X:\temp\dsh\tb3-home\taskboard\taskboard3.db`，与该表达式一致；
  但表达式本身没有单独测试（可见的只是「这个 profile 产出了库文件」）。
- ⇒ **新装 profile 必须自己给 `dataDir`**。照抄 bundle patch 而不加 profile 覆盖，
  会在 store 行激活时报 `dataDir 必须是非空字符串路径`。

**2026-11-28 实测的库**

```
X:\temp\dsh\tb3-home\taskboard\
├─ taskboard3.db                 122880 B  2026-11-27 13:55   ★ 任务板真实数据
├─ taskboard3-permissions.db       4096 B  2026-11-25 03:54   ← 来源不明，见下
├─ _global.db / 默认.db（+ wal/shm）                          ← taskboard2 时代遗留
```

- `taskboard3.db` 只有两张表：`cards` **44 行**、`kv` **41 行**；`workspaceSeq = 32`。
  按空间分：`ws28` 37 张、`ws31` 4 张、`ws2` / `ws32` / `ws6` 各 1 张。
- `taskboard3-permissions.db` **在仓库代码里找不到创建者**：全仓 `DatabaseSync` 只有
  `packages/io/src/sqlite.ts:71` 一处，`DB_FILE` 只有 `taskboard3.db`
  ⇒ 推断是历史版本 / 实验遗留（**未核实**），不要当现行 schema。
- `_global.db` / `默认.db` 是 taskboard2 时代文件（profile 注释说明复用
  `$DSH_HOME/taskboard/`），插件不读写；删之前先确认没有别的任务板在用。

### 2.2 运行时验收：装进 profile（AGENTS 没有这一节）

**隔离环境**

```powershell
$env:DSH_HOME='X:\temp\dsh\tb3-home'
```

不设会落到 `C:\Users\<你>\.dsh`（用户日常环境），会污染真实数据。

**一个 profile 的目录形状**（以 `tb3-isolated` 为例）

```
$DSH_HOME\profiles\<name>\
├─ package.json        ← dependencies 里 @taskboard/* 全是 link: 到某个 worktree 的 packages；
│                          dsh.profile.bundles 必须含 @taskboard/bundle
│                          （另有 @deepseek-ai/dsh-base、@deepseek-ai/dsh-web-app）
├─ cordis.patch.yml    ← profile 覆盖层：补 store 的 dataDir、禁用某行、改别的插件配置
├─ cordis.yml          ← 空入口 []；文件头明说别手改，改 patch
└─ node_modules\       ← dsh plugin / pnpm 装出来的链接
```

**装 / 改依赖的现行入口**

```powershell
& 'B:\DeepSeek Harness\0.2.2-rc2\resources\runtime\cli\bin\dsh.cmd' `
    plugin --profile tb3-isolated add <包名>
# install / remove / why 同理；参数原样转发 pnpm
```

本地 `link:` 依赖直接改 profile 的 `package.json`，再跑
`dsh plugin --profile <name> install`（没有仓库脚本代劳）。

⚠ **现有 21 个 profile 全是旧装配**（2026-11-28 实测 `package.json`）：

- 17 个只有 11 个 `@taskboard/*` link，**缺 `dsh-permissions`、`dsh-agent-loop`**；
- 4 个（`tb3-chip` / `tb3-estyle` / `tb3-load` / `tb3-space-check`）只有 8 个，
  还缺 `dsh-core` / `dsh-tools` / `dsh-agent-guard`。

当前 bundle patch 有 ②④⑥⑦⑧ 五行依赖这些包 ⇒ 17 个缺 ⑦⑧ 两行；4 个还缺 ②④⑥ 三行
（合计缺 5 行）。启动时会解析不到对应包（具体报错**未实测**）。要跑现状，先补齐
13 条 `@taskboard/*` link；最接近可用的是 `tb3-isolated`（只缺 2 条）。

**`scripts/link-worktree.mjs` 不是「切 profile」的脚本**（旧版本写错）

- 它给一个**新 worktree** 接 `node_modules`：顶层 junction 到主仓；每个包的
  `node_modules` 建真实目录 + 每个叶子 junction；`@taskboard/*` 指向**本 worktree**，
  第三方指向主仓 `.pnpm` 的**绝对真实路径**。
- 用法：`node scripts/link-worktree.mjs X:\temp\dsh\开发\<worktree>`；
  只验不建：加 `--verify`；仅 Windows（`mklink /J`）。
- 本 worktree 的实际做法是 `corepack pnpm install`（有 `node_modules/.modules.yaml`，
  `node_modules` 是真实目录），没有用这个脚本。AGENTS 规则 8 已在 2026-11-28 翻案
  「新建 worktree 里 `corepack pnpm install`（v12+）可用」；脚本头部
  「worktree 里永远不要跑 pnpm install」是 2026-11-19 的旧结论，按 AGENTS 执行。
- 切换 profile 指向哪个 worktree，只能改 profile 的 `link:`（仓库里没有代劳脚本）。
