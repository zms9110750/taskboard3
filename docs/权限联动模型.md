## 零、一句话

**DSH 下拉栏里注入两个任务板预设；任务板 UI 里显示全部档位但只能看不能选。**

---

## 一、用户裁定（原话）

> 按任务板权限，设置两个。一个是"任务版（工作区）"一个是"任务板（完全权限）"

> UI里面的权限档是给看不给选的。一定要放进UI的。

> 任务板UI里面的权限任何时候都可以打开这个下拉列表。
> 但是被dsh插件征用后，那个被合并的权限就不可被选择到他们。他们任何时候都可以选。只是可能不生效而已。

> 在 dsh 的只读下。就不能建卡，领取卡。
> 在 dsh 的权限改的时候是要告诉 core 的。他跟随变化到计划和开发者权限。

> 因为细节问题没必要给 dsh 开一堆权限。甚至以后加权限可能正交。组合不过来的。

## 二、注入 DSH 的两个预设

```ts
// 我们往 ctx.permissionPresets.presets 里注入两个（不是三个）
'taskboard-workspace': {
  sandbox: 'workspace-write',
  approval: 'ask',
  name: '任务版（工作区）',
  description: '任务板管工具权限：领到工作卡才拿到该卡授予的工具。',
},
'taskboard-full': {
  sandbox: 'danger-full-access',
  approval: 'ask',
  name: '任务板（完全权限）',
  description: '沙盒不限制，但任务板仍按卡片管工具权限。',
},
```

**为什么是两个**：这两个对应「沙盒层」的两档。
任务板内部的细档（计划 / 工作 / 自动）是**另一维度**，不往 DSH 开。

⚠ **`taskboard-full` 的 approval 填 `ask` 还是 `never`？**
DSH 的 `danger-full-access` 出厂是 `approval: never`。
但我们只想放开沙盒、不想放开审批 ⇒ 我选 `ask`。**这条待用户确认。**

## 三、简化：只剩「两种沙盒 × 三种任务板模式」

### 3.1 沙盒层（DSH 管的）

| 我们在 DSH 注入的 | sandbox | 含义 |
|---|---|---|
| `taskboard-workspace` | `workspace-write` | 工作区内可写 |
| `taskboard-full` | `danger-full-access` | 沙盒不限制 |

### 3.2 任务板模式层（core 管的）

| 模式 | 能不能建卡 | 能不能领卡 | 工具权限 |
|---|---|---|---|
| `plan` | ❌ | ❌ | 只有 BASE |
| `work` | ✅ | ✅ | 领到卡才拿额外工具 |
| `auto` | ✅ | ✅ | 同 work + AI 能自己采纳 |

⚠ **`developer` 档取消** —— 用户说「两个」，没有第三个。

## 四、任务板 UI 里的权限下拉

### 4.1 永远显示全部档位，但「给看不给选」

用户原话：

> UI里面的权限档是给看不给选的。一定要放进UI的。

⇒ **下拉列表里所有档位都显示**，但：
- 当前生效的那个：**选中态**
- 其它：**灰掉不可点**，每档带说明

### 4.2 联动时（DSH 插件）的映射

| DSH 选的是 | core 认为是 | UI 里显示 |
|---|---|---|
| `read-only`（仅可查看）| **plan** | plan 高亮，其它灰；说明「当前由 DSH 的『仅可查看』接管：不能建卡、不能领卡」|
| `workspace-write`（工作区内修改）| **work** | work 高亮；说明「当前由 DSH 的『工作区内修改』接管」|
| `danger-full-access`（完全权限）| **work + 沙盒不限制** | work 高亮；说明「当前沙盒不受限，但工具权限仍按卡」|
| `taskboard-workspace`（我们注入的）| **听任务板 UI 的** | 任务板 UI 里可切 plan/work/auto |
| `taskboard-full`（我们注入的）| **听任务板 UI 的** | 同上，沙盒不限制 |

⚠ **`danger-full-access` 映射成 `work` 还是 `auto`？**
用户说「跟随变化到计划和开发者权限」——
**「开发者权限」在旧模型里 = 完全访问 = 不设防**。
但现在没有 developer 档了。
⇒ **待用户确认**：DSH 选完全权限时，任务板是「work」还是「auto」还是不设防？

### 4.3 不联动时（MCP / 别的宿主）

**仍然显示全部档位，但仍然给看不给选。**

因为没有任务板预设可选 —— 用户没选「按任务板权限」，任务板就不管。
UI 只是告诉用户「现在是 DSH 的 X 权限，任务板不管」。

⚠ **MCP 场景下根本不知道宿主权限** ⇒ UI 显示「无法获知宿主权限」。

## 五、实现要点

### 5.1 core 要改

```ts
/** 任务板模式。去掉 developer（用户 2026-11-19：只设两个预设）。 */
export type BoardMode = 'plan' | 'work' | 'auto';

/** 我们在 DSH 注入的两个预设。 */
export const BOARD_PRESETS: readonly BoardPreset[] = [
  { name: 'taskboard-workspace', sandbox: 'workspace-write', label: '任务版（工作区）', … },
  { name: 'taskboard-full',      sandbox: 'danger-full-access', label: '任务板（完全权限）', … },
];

/**
 * DSH 自己的预设名 → 任务板模式。
 *
 * ⚠ 实测来源：`C:\Users\16229\.dsh\profiles\desktop\cordis.patch.yml`
 *   出厂默认只有 2 个，但这个 profile 的 patch 覆盖成 3 个：
 *   read-only / workspace-write / danger-full-access
 */
export const MODE_OF_HOST_PRESET: Readonly<Record<string, BoardMode>> = {
  'read-only': 'plan',
  'workspace-write': 'work',
  'danger-full-access': 'work',   // ⚠ 待确认：work 还是 auto 还是不设防
};

/**
 * UI 权限下拉的每一项。
 *
 * 用户 2026-11-19：「UI里面的权限档是给看不给选的。一定要放进UI的。」
 * ⇒ 全部档位都返回，`selectable` 决定能不能点。
 */
export interface PermissionOption {
  readonly mode: BoardMode;
  readonly label: string;
  readonly description: string;
  readonly selectable: boolean;
  /** 不可选时的说明（如「已合并到 DSH 的『仅可查看』」）。 */
  readonly reason: string;
  /** 是不是当前生效的那个。 */
  readonly active: boolean;
}

export function permissionOptionsOf(input: {
  /** 宿主当前预设名。`undefined` = 宿主没有权限服务（MCP）。 */
  readonly hostPreset: string | undefined;
  /** 用户在任务板 UI 里选的模式（只在宿主选了我们的预设时有效）。 */
  readonly boardMode: BoardMode | undefined;
}): readonly PermissionOption[];
```

### 5.2 dsh 要改

**只注册两个预设**（不是三个）。

**每次用的时候读当前联动态**：

```ts
// guard 每次判工具调用时：
const hostPreset = ctx.permissionPresets?.current(sessionEvents);
const boardMode = boardModeOf(hostPreset) ?? userChosenMode;
```

⚠ **`current()` 要传 `sessionEvents`。** 每次调用都读一次（用户已确认可以）。

### 5.3 HTTP 加字段

```ts
GET /api/state → {
  ...,
  permission: {
    /** 宿主当前预设名；`undefined` = 宿主没有权限服务。 */
    hostPreset?: string,
    /** 全部档位 + 可不可选 + 说明。UI 直接渲染，不判断。 */
    options: PermissionOption[],
  }
}
```

### 5.4 UI

`permissionOptionsOf()` 返回的表直接渲染：

```
┌──────────────────────────────────────────┐
│ ● 计划                                    │
│    不能建卡、不能领卡                      │
│    当前由 DSH 的「仅可查看」接管            │  ← 高亮
│ ○ 工作          (灰)                      │
│    领到卡才拿额外工具                      │
│ ○ 自动工作      (灰)                      │
│    AI 可以自己采纳草稿                     │
└──────────────────────────────────────────┘
```
