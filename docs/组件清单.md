## 〇、三层分离（`2026-11-17` 用户要求）

用户：
> 「开发中的组件放在 dev 文件夹。组件，展示组件的 html，都分开。
>  在确认组件可用以后再把 ts 放回去 src」

```
packages/dsh-client/
├─ src/          ← 产品代码（打进插件、发 npm）
├─ test/         ← 产品代码的测试
└─ dev/          ← 开发中，完全不参与产品构建
   ├─ pure/       ┐
   ├─ components/ ├ 组件本体（未定稿）
   ├─ test/       ┘
   ├─ preview/    ← 展示脚手架（入口 / CSS / 构建 / 验证）+ index.html
   └─ shots/      ← verify 跑出来的截图
```

**为什么**：`src/preview/main.tsx` 放在 `src/` 下时，`tsc -b` 给它出了
`lib/preview/main.d.ts`，而 `files: ["lib"]` 会把它发到 npm。

**构建**：

```powershell
# 组件本体 + 单测（在 dev 里）
node packages/dsh-client/dev/preview/build.mjs     # → dev/preview/index.html（双击看）
node packages/dsh-client/dev/preview/verify.mjs    # CDP 断言
node --test packages/dsh-client/dev/test/*.test.ts # 纯逻辑单测

# 产品（不含 dev）
tsc -b packages/*                                  # dev/ 不在 include 里
```

## 一、为什么按这个顺序

**依赖序**，不是重要性序：

```
pure（纯逻辑，可单测）
  ↓
叶子组件（不依赖别的组件）
  ↓
复合组件（拼叶子）
  ↓
视图（拼复合）
```

⇒ 越靠前的越先做，因为后面的**没有它编译不过**（不是「不好看」）。

### C3b · `src/types.ts` 的 `Card` 修正（`2026-11-17`）

⚠ **发现 `dsh-client/src/types.ts` 的 `Card` 与 core 的 `Card` 差三个字段**：

| core 有 | client 有 |

### C5 · `SpaceBar` —— ✅ 可用（待迁 src，已在 main）

| 项 | 值 |
|---|---|
| 文件 | `dev/pure/space-bar.ts`（285 行）+ `dev/components/SpaceBar.tsx`（166 行）|
| 旧版对应 | **`views/card-list/board-row.js`（251 行）** ← 不是 toolbar.js |
| 单测 | `dev/test/space-bar.test.ts`（369 行，**50 条**）|

| CDP | **68 条断言**，连跑 3 遍一致 |
| 定稿日期 | `2026-11-17` |

**四行表（这个组件的全部难点）**：

| 显示已归档 | 选中空间 | 按钮文案 | 禁用 | 行为 |
|---|---|---|---|---|
| 关 | 不是当前 | `激活此为当前空间` | 否 | 把正在查看的变成激活 |
| 关 | 就是当前 | `当前空间` | **是** | 无 |
| 开 | 不是当前（未归档）| `已归档`（未选中）| 否 | 切换归档状态 |
| 开 | 不是当前（已归档）| `已归档`（选中）| 否 | 切换归档状态 |
| 开 | **当前（未归档）** | `当前空间` | **是** | 无；**不显示「已归档」**（防误导）|
| 开 | **当前（已归档，异常态）** | `已归档`（选中）| **否** | 点 → 取消归档，修回正常 |

**两条核心语义（用户原话）**：

1. **chip 点击 = 查看，不是激活**
   > 「我要的切换。是对我展示啊。不是自动切换激活空间啊。那个激活按钮还是要的。查看和激活是要分离的。」

   CDP 实证：点 chip 只派发 `view:ws-code`，`activate` 一条都没有，`data-current` 不变。

2. **只有一个按钮**
   > 「不是下拉框，不是菜单。是一个按钮。」
   > 「我要的不是两个独立按钮，是一个独立按钮。」

   CDP 实证：左侧 `.space-bar__actions` 恰好 2 个按钮（那**一个** + 「显示已归档」）。

**成员补的、任务描述没写的一条**：

`resolveViewingId` 的回落链（旧版 `board-row.js:55-57`）—— 显式 viewingId 不可见时
**回落到 currentId**，而不是显示「一个都没选中」。不补的话关掉「显示已归档」那一刻
按钮会莫名其妙变禁用。

**旧版源码本身有三处矛盾**（成员报告的）：

| 位置 | 矛盾 |
|---|---|
| `board-row.js:22-27` | 注释说「显示已归档=关」时按钮**不显示**，但代码 `:125-148` 是**显示** |
| `board-row.js:4-9` vs `:78-85` | 同一个文件里「chip 点击即激活」和「chip 点击只查看」两种互斥口径并存（09 号前半/后半）|
| `board-row.js:76` | title 里有 `**` markdown 笔误，浏览器不渲染，用户会看到星号 |

⇒ 均按**代码 + 任务描述**做（成员判断正确）。
