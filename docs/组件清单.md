## 二、三处入口：同一套 DOM，只有视口不同

```ts
// src/client.tsx:90-106
panelEntry(id, order, label, Icon, Body)
  → { panellist: { name:'sidebar.panellist', id, order, label },
      main:      { name:'main', key: id, label },
      Icon, Body }
const PANEL_ENTRY = panelEntry(PANEL_ID, PANEL_ORDER, '任务板', TaskboardIcon, WorkspaceBody)
```

- **同一个 `WorkspaceBody` 直接注册三处**（右侧页签 / 左侧栏 / 抽屉），没有 wrapper、
  没有 `density` 参数：能不能放下（工具栏换行、分栏横/竖）由容器宽度自己决定
  （`@container tb3w` 的职责）。
- `panellist.id` 必须等于 `main.key`，两处 `label` 也必须一致 —— 工厂同时产出两份，
  避免改一处漏一处后**静默错位**。
- 三处各是独立实例 ⇒ 各自一份 loading / 选中卡状态；**UI 状态（组 + 折叠）按空间
  分片共享**（见 5.3）。

用户 `2026-11-23`（引自 `src/client.tsx:124-136`）：

> 「用同一套dom。让他们的视口不一样。但是视口内用同一个组件。」
> 「视口组件以工作区的那个为准。」

## 三、`Workspace` 的结构（谁画哪块）

`src/renderers/Workspace.tsx` **只做拼装 + 布局**（不拉数据、不发请求）：

| 工具栏（计数 / 图例 / 领卡权限 / 空间 ▾ / 视图切换 / 新建） | `WorkspaceToolbar` + `CardActionControl` | `renderers/workspace/WorkspaceToolbar.tsx`、`.../CardActionControl.tsx` |
| 筛选行（状态 / 类别 / 领域三棵树 + 尾部搜索框） | `FilterRow` + `FilterBox` + `SearchBox` | `renderers/FilterRow.tsx`、`FilterBox.tsx`、`SearchBox.tsx` |
| 列表头 / 空态 | `ListHeader` / `ListEmpty` | `renderers/workspace/ListHeader.tsx`、`ListEmpty.tsx` |
| 列表（行式） | `CardRow` × N | `renderers/CardRow.tsx` |
| 科技树（`view = 'tree'` 时占满列表栏） | `TechTree`（内含 `TreeCard`、`SiblingRelationPanel`） | `renderers/TechTree.tsx`、`TreeCard.tsx`、`SiblingRelationPanel.tsx` |
| 列表 / 详情之间的可拖分隔条 | `SplitHandle`（只上报列表占比，不改尺寸） | `renderers/workspace/SplitHandle.tsx` |
| 详情 | `CardDetail`（含 `DetailHead` / `DetailNote` / `DetailHistory`） | `renderers/CardDetail.tsx` |
| 状态菜单（锚点是详情里的状态格 `[data-meta="status"]`） | `StatusMenu` | `renderers/StatusMenu.tsx` |
| 派生子任务浮窗 | `DeriveMenu`（portal 到 body） | `renderers/DeriveMenu.tsx` |
| 建卡整页（打开时**整个替换** Workspace，不是浮层） | `CreateFlow` → `CardCreate` | `src/CreateFlow.tsx`、`renderers/create/*` |

**布局两个维度**（判据是宽，不是面积）：宽（> 700px）列表 flex:2 / 详情 flex:1.2（min 300 / max 460）；
窄（≤ 700px，570×920 真实 tab）上下堆叠、列表 52%、详情剩余约 45%。
百分比是**量出来的**（`Workspace.tsx:34-52` 的注释记了量法；AGENTS 3.8）。

**数据入口**：`src/WorkspaceBody.tsx` 把数据层与界面焊在一起：
`useBoardState()`（`src/store.ts`）→ `<Workspace …/>`。
它自己持两个纯视图状态（`showArchived` / `selectedId`），筛选与搜索**不在** body 里
（`Workspace` 自己按 `pure/card-filter.ts` 就地过滤，不匹配的卡根本不渲染）。

## 五、三条关键链路（写清「谁调谁」，避免下一个人重查）

### 5.1 ask 作答链（从点击到落库）

```
AskOptionRow / AskCustomRow（点选项 或 自填失焦）
  → AskSection.onAsk(sectionId, groupIndex, action: AskAction)
  → CardDetail：askPayloadAfter(source, groupIndex, action)（内部 applyAskAction，:225-233）
  → onSectionChange(sectionId, next)
  → Workspace → WorkspaceBody.onSectionChange(cardId, sectionId, patch)
  → actions.patchSection(cardId, sectionId, patch)            // store.ts:279
  → store 乐观改本地卡 + 同一张卡 PATCH 串行
  → api.patchCard({ workspaceId, cardId, content })           // 整份 content
  → 成功用服务端回声覆盖；失败回滚到改前那张卡并置 error
```

| 环节 | 语义 | 路径 |
|---|---|---|
| 选项点选 | **即点即提交**（一次动作一次 PATCH） | `AskSection.tsx:146-185`（`AskOptionRow`）、`CardDetail.tsx:39-51` |
| 自填输入 | **失焦才提交**（本地草稿，按键不写库） | `AskSection.tsx:176-271`（`commit` 在 `:207-210`，`onBlur` 在 `:261`） |
| 乐观 + 串行 | 先改本地卡；`sectionWriteChain` 保证同一张卡上一笔结束才发下一笔；序号 `sectionSeq` 丢弃过期回声 | `store.ts:305-359` |
| 整份覆盖 | `patchCard` 的 `content` 是整份，必须用**当前全部章节**组装 | `store.ts:273-305`；`pure/section-edit.ts` 的 `contentOfSections()` |

### 5.2 card 权限轴（单轴 store，2026-11-27 拆分后）

- `CardActionControl` 只读 `useCardPermission()`；挂载时 `ensureCardPermissionLoaded()`，
  **每次打开下拉强制 `refreshCardPermission()`** —— 补偿「另一个包改了 card 轴不会通知本 store」。
- 保存：乐观改选中 → `POST /permission` **只带 `cardActionLevel`** → 成功用回声覆盖 /
  失败回滚并提示。四个「不发」：没就绪 / 同值 / 已有保存在飞 / 值不在选项表。
- 路径：`CardActionControl.tsx`、`pure/card-permission-state.ts:119-194`。

### 5.3 UI 状态按空间分片（B-8，lead `2026-11-28`）

- `uiStateStore` 是模块级单例，但内部是 `Map<workspaceId, snapshot>`：对空间 X 的
  commit / GET **只碰 X**，别的空间的快照对象身份不变 ⇒ 无关变化不触发重渲染。
- **「哪个入口在看哪个空间」不在 store 里**：组件持 `viewingId`，用
  `useUiState(workspaceId)` 只订阅自己那个键、只对自己那个键发操作。
- 保存防抖 / 在飞 PUT 也按空间各一个槽。
- 路径：`ui-state-store.ts`、`use-ui-state.ts`、`pure/ui-state.ts`。

### 5.4 抽屉两槽共享状态

入口（`conversation.input.left`）和面板（`conversation.input.overlay`）是两个独立槽条目，
渲染在不同位置 ⇒ **只能靠模块级 `drawer-state` 同步**（各自 `useSyncExternalStore`）。
试过 `inject(sessionId)` 让 DSH 注入 store，**实测崩了**（`props.hooks` 是 `undefined`）；
现行做法抄 `taskboard2`。路径：`pure/drawer-state.ts`、`register-drawer.tsx`。
