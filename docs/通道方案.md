# Host ↔ Client 通道方案

> ⚠ **决策记录（2026-11-13 的调研）。结论已落地：** Host↔Client 走
> **自注册 HTTP 路由**（`packages/dsh/src/http.ts`，`createHandler` / `mountRoutes` / `ROUTE_PREFIX`），
> 例外是 AI 工具——它在同进程直接 `inject: ['taskboard3Core']` 调 core，不走 HTTP。
> 历史论证保留原样，不反映当前实现。

> 调研任务 `task-4`。**只做调研，未写任何生产代码。**
> 标注约定：**【读到】** = 有源码依据，附路径与行号；**【推断】** = 由读到的事实推出，未实测。

---

## 先讲清「数据通道」是什么

浏览器里跑着 DSH 的 React 页面。任务板的数据在另一个地方——**Node 进程里的 `core`**。这两者之间隔着一条 HTTP 连接。任何一次「点开任务板看到一个卡片列表」，都是浏览器里的组件**发一个 HTTP 请求**出去，Node 进程里的代码**读 SQLite、返回 JSON**，组件再把它画出来。

**「数据通道」就是这条 HTTP 往返用什么协议、走哪个 URL、谁校验调用者身份。**

DSH 提供两条修路的方式：

- **A. 自己注册一条 HTTP 路由**：`ctx.webServer.register({ kind:'prefix', path:'/taskboard3', handler })`，然后在浏览器里 `fetch('/taskboard3/api/state')`。就是普通 web 开发，但要自己写鉴权。
- **B. Typert Remote**：Host 侧给一个类的方法打 `@Remote` 装饰器，跑一次代码生成，浏览器里就出现 `ctx.remote.taskboard3.list()` 这样的**类型化方法**。不用写 fetch，不用自己鉴权（框架替你做了），但需要额外一套构建步骤。

「session scope」在 Q1.4 单独讲。

---

## 结论

**选 A（自己注册 HTTP 路由），混合一个例外。**

理由三条，都有源码依据：

1. **B 的生成器不随 DSH 安装分发**。`@deepseek-ai/dsh-typert-generator` 在安装包里**不存在**（我逐个列了 `node_modules/@deepseek-ai/` 下所有 160+ 个包，没有 typert-generator，也没有任何构建期 typert 工具）。这意味着第三方插件作者拿不到那条生成链。
2. **A 的鉴权成本很低**：DSH 已经把这套封装成一个同步函数调用，两行代码。
3. **taskboard 不需要流**：全量读 1000 张卡 4.1ms、769KB，一次请求足够；写操作是低频 CRUD。

例外：**AI 工具那条路不要走 HTTP**，它在同一个进程里直接调 `core`（`inject: ['taskboard3Core']`）。无所谓通道。

## Q1.2 鉴权：`admit` 收什么，怎么调

**【读到】** `WebRoute.handler` 拿到的是 **node 原生对象**，不是 Fetch `Request`：

`dsh-host-webserver/src/index.ts:52-58`

```ts
export interface WebRoute {
  kind: WebRouteKind
  path: string
  /** Owns the full response lifecycle (may hold the response open, e.g. SSE). */
  handler: (req: IncomingMessage, res: ServerResponse) => void | Promise<void>
}
```

**【读到】** `admit()` 的入参是 `ConnectionTrustRequest`，它**只要求 `headers`**，而且接受两种形态：

`dsh-client-connection/src/rpc.ts:98-101`

```ts
export interface ConnectionTrustRequest {
  /** Request headers supplied by either the Fetch or node:http representation. */
  readonly headers: Headers | Readonly<Record<string, string | readonly string[] | undefined>>
}
```

`dsh-client-connection/src/api-request-trust.ts:18-22` 证实两种都处理：

```ts
function header(headers: ConnectionTrustRequest['headers'], name: string): string | undefined {
  if (headers instanceof Headers) return headers.get(name) ?? undefined
  const value = headers[name]
  return typeof value === 'string' ? value : undefined
}
```

**【读到】** 所以**直接把 node 的 `req` 传进去就行**，不用构造 Fetch `Request`。因为 `IncomingMessage` 有 `headers` 属性，结构上满足 `ConnectionTrustRequest`。

**【读到】** `admit` 返回两种结果（`rpc.ts:118-121`）：

```ts
export type PeerAdmission =
  | { readonly peer: PeerScope }
  | { readonly rejection: 401 | 403 }
```

**【读到】** `admit` 内部做两件事（`rpc-host.ts:129-137`）：

```ts
admit(request: ConnectionTrustRequest): PeerAdmission {
  if (!this.isTrusted(request)) return { rejection: 403 }     // Host/Origin 围栏
  if (this.disposed) return { rejection: 401 }
  const secure = this.owner.get('webServer')?.protocol === 'https:'
  if (this.browserAuth.isAuthenticated(request, secure)) return { peer: this.browserPeer }
  const id = this.browserAuth.authenticateApi(request, secure)
  const record = id === undefined ? undefined : this.peers.get(id)
  return record === undefined ? { rejection: 401 } : { peer: record.peer }
}
```

403 = Host/Origin 不像自己人（防 DNS rebinding，见 `api-request-trust.ts:113-151` 的长注释）；401 = 没有有效浏览器 cookie 或 API 凭据。

**【读到】** 还有一个更轻的变体，只要「能不能过」不要 `peer`（`rpc-host.ts:122-126`）：

```ts
requestRejection(request: ConnectionTrustRequest): ConnectionRequestRejection {
  const admission = this.admit(request)
  return 'rejection' in admission ? admission.rejection : undefined
}
```

## Q1.3 写操作：裸 handler 里怎么鉴权（可运行片段）

**【读到】** 真实用法在 `dsh-host-open-in-app/src/index.ts:184-191`。这是 DSH 自家的插件，照着抄：

```ts
/** Trust surface consumed here; the browser-side connection package owns the full type. */
interface OpenInAppConnection {
  requestRejection(request: { readonly headers: IncomingMessage['headers'] }): 401 | 403 | undefined
}

/** The composition's connection service (typed locally: its package is browser-side). */
function connectionOf(ctx: Context): OpenInAppConnection {
  return Reflect.get(ctx, 'connection') as OpenInAppConnection
}

/** Answer an untrusted/unauthenticated request; true when it was rejected. */
const rejected = (req: IncomingMessage, res: ServerResponse): boolean => {
  const rejection = connectionOf(ctx).requestRejection(req)
  if (rejection === undefined) return false
  res.statusCode = rejection
  res.end()
  return true
}
```

**注意它没有 `inject` 完整类型的 `connection`**，而是自己声明了一个窄接口 `{ requestRejection(req) }`，用 `Reflect.get(ctx, 'connection')` 取。原因写在注释里：

> typed locally: **its package is browser-side**

**【读到】** 它的 `inject` 声明（`index.ts:47`）：

```ts
export const inject = ['webServer', 'connection', 'subprocess']
```

**【读到】** 三个路由的完整写法在 `index.ts:193-311`：GET apps（`kind:'exact'`）、GET icon（`kind:'prefix'`）、POST open（`kind:'exact'`）。每个都以 `if (rejected(req, res)) return` 开头，然后自己判 method，返回 405。

**【读到】** POST 的 body 处理（`index.ts:107-121`）——**64 KiB 上限，超了先 `req.resume()` 排空再回 413**：

```ts
async function readBoundedBody(req: IncomingMessage): Promise<string | null> {
  const chunks: Buffer[] = []
  let size = 0
  for await (const chunk of req as AsyncIterable<Buffer>) {
    size += chunk.byteLength
    if (size > MAX_BODY_BYTES) {
      // Drain the remainder so the refusal is a readable response, not a socket cut.
      req.resume()
      return null
    }
    chunks.push(chunk)
  }
  return Buffer.concat(chunks, size).toString('utf8')
}
```

### taskboard3 的写法（按上面抄）

```ts
import type { IncomingMessage, ServerResponse } from 'node:http'
import type { Context } from '@deepseek-ai/cordis'

export const inject = ['webServer', 'connection', 'taskboard3Core']

/** connection 的窄面：只要鉴权，不要 RPC。 */
interface TrustFence {
  requestRejection(req: { readonly headers: IncomingMessage['headers'] }): 401 | 403 | undefined
}

const fence = (ctx: Context): TrustFence =>
  Reflect.get(ctx, 'connection') as TrustFence

function sendJson(res: ServerResponse, status: number, payload: unknown): void {
  res.statusCode = status
  res.setHeader('content-type', 'application/json; charset=utf-8')
  res.setHeader('cache-control', 'no-store')
  res.end(JSON.stringify(payload))
}

async function readJson(req: IncomingMessage, max = 1024 * 1024): Promise<unknown> {
  const chunks: Buffer[] = []
  let size = 0
  for await (const chunk of req as AsyncIterable<Buffer>) {
    size += chunk.byteLength
    if (size > max) { req.resume(); return undefined }
    chunks.push(chunk)
  }
  return JSON.parse(Buffer.concat(chunks, size).toString('utf8')) as unknown
}

export function apply(ctx: Context): void {
  const tb = () => ctx.taskboard3Core   // 见下方【推断】关于服务名

  // ── GET：读整个空间 ──
  ctx.effect(() => ctx.webServer.register({
    kind: 'exact',
    path: '/taskboard3/api/state',
    handler: async (req, res) => {
      const rejection = fence(ctx).requestRejection(req)
      if (rejection !== undefined) { res.statusCode = rejection; res.end(); return }
      if (req.method !== 'GET') { res.statusCode = 405; res.setHeader('allow', 'GET'); res.end(); return }

      const url = new URL(String(req.url), 'http://localhost')
      const workspaceId = url.searchParams.get('workspace') ?? ''
      sendJson(res, 200, { ok: true, data: tb().state(workspaceId) })
    },
  }), 'taskboard3: GET /api/state')

  // ── POST：写一张卡 ──
  ctx.effect(() => ctx.webServer.register({
    kind: 'exact',
    path: '/taskboard3/api/cards',
    handler: async (req, res) => {
      const rejection = fence(ctx).requestRejection(req)
      if (rejection !== undefined) { res.statusCode = rejection; res.end(); return }
      if (req.method !== 'POST') { res.statusCode = 405; res.setHeader('allow', 'POST'); res.end(); return }
      if (String(req.headers['content-type']).split(';', 1)[0]?.trim().toLowerCase() !== 'application/json') {
        sendJson(res, 415, { ok: false, code: 'UNSUPPORTED_MEDIA_TYPE' }); return
      }

      let body: unknown
      try { body = await readJson(req) } catch { body = undefined }
      if (body === undefined) { sendJson(res, 400, { ok: false, code: 'BAD_REQUEST' }); return }

      const result = await tb().create(body)      // 校验在 core
      if (!result.ok) { sendJson(res, 400, result); return }
      sendJson(res, 200, { ok: true, data: { card: result.card } })
    },
  }), 'taskboard3: POST /api/cards')
}
```

**【推断，未验证】** 上面 `ctx.taskboard3Core` 这个服务名是假设的。真正实现时要先确认 Host 插件用什么方式把 `core` 的实例暴露出来——`provide()` 一个服务，或者干脆在同一个 `apply` 里闭包持有。

**为什么不走 `register({ resource })`**：`dsh-host-webserver/README.md:63` 写明 resource 形态在 HTTP 下只接 `GET`/`HEAD`：

> A named route may give `resource(request, peer?)` instead of `handler`: a function from a Fetch `Request` to a `Response`. **Over HTTP only `GET` and `HEAD` reach it** — any other method is answered 405 with `Allow: GET, HEAD` and its body is never read.

所以写操作**必须**用裸 `handler`。既然写操作要裸 handler、要自己读 body、要自己鉴权，读操作也用裸 handler 反而更一致（一套代码，一处鉴权）。

## Q1.4 流/订阅：taskboard 需不需要

**不需要。**

数据量（来自 `docs/设计.md` 与 lead 的实测）：

| 项 | 值 |
|---|---|
| 1000 张卡全量 JSON | 769 KB |
| SQLite 全量读 1000 条 | 4.1 ms |
| 单张卡写入 | 1.47 ms |

**【推断】** 客户端首次加载拉一次全量，之后每次写操作由响应带回「变更的卡 + 连带重算的卡」，客户端就地更新内存，**不需要订阅**。多人/多窗口同时编辑同一空间的场景不存在（单用户本地插件）。

如果真的需要，SSE 可以后加：`handler` 可以持有 `res` 不 end（`dsh-host-webserver/src/index.ts:56` 的注释明确说「may hold the response open, e.g. SSE」）。

### 「session scope」是什么（用户追问）

**【读到】** Typert 的 `@RemoteScope(key)` 是「按某个身份收窄的 receiver」，`TypertContextMap` 把「scoped Context 种类」映射到「wire 身份」。

`dsh-typert-protocol/README.md:67`：

> A business package declares the association through the merge-extensible `TypertLookupMap` and `TypertContextMap`. **A Host Context adapter owns the stable wire declaration and resolves wire identities to live Contexts.**

`dsh-client-connection/src/index.ts:61-73` 有对应的 Host 侧 waterfall 事件 `connection/request(request, response, next)`。

**【推断】** 「session scope」= Remote 调用可以声明「我这次调用属于哪个 session」，然后框架用它做两件事：① 权限判定（谁能调谁的 session）② 把 session 相关的上下文（agent、事件流）注入到调用里。

**taskboard3 不需要它**：任务板数据按 `workspaceId` 分区，和「哪个聊天会话」无关。用户已经裁定「激活」不是 core 的概念，是各入口的策略。**这正是选 A 而不是 B 的第二个理由——用了 B 就被绑进 session scope 的模型里。**

### 路径约定的关键细节：文档相对路径

**【读到】** `dsh-host-open-in-app/src/shared.ts:10-26`：

```ts
/** GET route path serving the probed application ids. */
export const OPEN_IN_APP_APPS_PATH = '/open-in-app/apps'

/** Browser-relative form of {@link OPEN_IN_APP_APPS_PATH}. */
export const OPEN_IN_APP_APPS_ROUTE = OPEN_IN_APP_APPS_PATH.slice(1)
```

**Host 注册的是 `/open-in-app/apps`（以 `/` 开头），浏览器 fetch 的是 `open-in-app/apps`（去掉前导 `/`）。**

原因写在 `shared.ts:1-8` 的文件头注释：

> Each route carries **the absolute pathname the Host registers beside the document-relative form the browser addresses**

**【推断】** 这是**必须照抄的规矩**。浏览器页面挂在某个子路径下（比如 dsh web 的挂载点可能不是 `/`），绝对路径 `/taskboard3/api/state` 会跳出挂载点。用相对的 `taskboard3/api/state` 才跟着页面走。

⇒ **taskboard3 的路径常量要成对定义，并且共用同一个模块**：

```ts
export const TB_STATE_PATH = '/taskboard3/api/state'
export const TB_STATE_ROUTE = TB_STATE_PATH.slice(1)   // 浏览器用这个
```

**【读到】** 这个 shared 模块通过 `package.json` 的 `./shared` 子路径导出，Browser-safe（只有常量和类型）——Host 和 Client 两侧都 import 它，保证路径不会写两份。

### 打开这个标签页

## 落地建议

```
packages/dsh/
├─ src/host/
│  ├─ index.ts         apply：provide 服务 + 注册路由
│  ├─ routes.ts        三个路由（state / cards / card 写入）
│  └─ trust.ts         fence() 薄封装（照抄 open-in-app）
├─ src/client/
│  ├─ index.ts         apply：注册 tab type + body slot
│  ├─ definition.ts    SidebarRightTabDefinition
│  ├─ BoardBody.tsx    body 组件，用 useTabInfo()
│  └─ api.ts           fetch 封装（Host 相对路径）
└─ src/shared/
   └─ routes.ts        PATH / ROUTE 成对常量（两侧共用）
```

**必须注意的坑（都来自源码）**：

1. **浏览器 fetch 用相对路径**，不能用 `/taskboard3/...`（`shared.ts:13-14`）
2. **写操作必须裸 handler**，`resource` 只接 GET/HEAD（`README.md:63`）
3. **鉴权用 `requestRejection(req)`**，直接把 node 的 `req` 传进去（`rpc.ts:98-101` 的 `ConnectionTrustRequest` 只要求 `headers`）
4. **一个 `kind` 只能有一个 `builtin` 注册**，所以 `kind: 'taskboard3'` 和 `id` 都不能撞（`tab-registry.ts:258-262`）
5. **注册必须在 `ctx.effect` 里**，返回 disposer（`tab-registry.ts:270-280` 自己就是 effect-owned）

## 未能确认的事

1. **`ctx.taskboard3Core` 服务名**：【推断】。需要看实际实现怎么把 core 实例暴露给路由 handler。可以在同一个 `apply` 闭包里直接持有，不需要 provide 服务。
2. **DSH web 页面的实际挂载路径**：如果页面挂在 `/`，绝对路径也能用；如果挂在子路径（如 `/session/xxx/`），必须用相对路径。`shared.ts` 的注释暗示「页面挂载点可能不是根」，但没写具体是什么。**实现时必须实测一次。**
3. **Typert 生成器能否单独获取**：我只确认了 DSH 安装包里没有。npm 上有没有独立发布的 `@deepseek-ai/dsh-typert-generator` 我没查（`access: restricted`，大概率下载不到）。
4. **窗口多开（同一 Host 两个浏览器标签页）时的一致性**：纯 HTTP 轮询/请求-响应模型下，A 标签页的修改不会推给 B。单用户场景可不处理，但**未验证是否实际存在这种用法**。
